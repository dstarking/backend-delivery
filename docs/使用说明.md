# backend-delivery Skill v1.0.0｜安装与使用

此包供 **Windows Codex 和 Claude Code** 使用，包含统一工作流、6 份阶段执行说明、10 份 Markdown 文档模板、文档初始化/校验脚本，以及 Windows 安装脚本。无需第三方 Python 依赖。

## 1. 安装（手动）

解压 `backend-delivery-skill-v1.0.0.zip`，得到 `backend-delivery` 文件夹：

- Codex 全局：`C:\Users\<用户名>\.agents\skills\backend-delivery\SKILL.md`
- Codex 项目：`<仓库根目录>\.agents\skills\backend-delivery\SKILL.md`
- Claude Code 全局：`C:\Users\<用户名>\.claude\skills\backend-delivery\SKILL.md`
- Claude Code 项目：`<仓库根目录>\.claude\skills\backend-delivery\SKILL.md`

**建议：** 经常跨项目开发时安装为全局 skill。若想团队共享，可安装到单个仓库并纳入 Git 版本管理。Codex 与 Claude Code 需要各自的发现目录，互不自动同步。

## 2. 安装（PowerShell 自动）

在解压目录的父目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\backend-delivery\scripts\install_windows.ps1 -Target Both -Scope User
```

如果只装 Codex，将 `-Target Both` 改为 `-Target Codex`；只装 Claude Code 则改 `-Target Claude`。项目级安装示例：

```powershell
powershell -ExecutionPolicy Bypass -File .\backend-delivery\scripts\install_windows.ps1 -Target Codex -Scope Project -Repo "C:\code\your-repo"
```

安装脚本不会覆盖已有同名 skill。需要时重启应用/新开会话以使其被发现。

## 3. 触发语句

- Codex CLI/IDE：`$backend-delivery`。Codex Desktop 可在任务里写“使用 backend-delivery skill”。
- Claude Code：`/backend-delivery`。

首次推荐：

> 使用 backend-delivery Skill，通过已经安装的 BrowserSkill 阅读这个需求网页：<需求 URL>，按后端业务模块拆分，统计独立后端需求，给出依赖与开发顺序。项目 ID：sorting-optimization。先只做需求分析，不修改代码。完成后生成技术方案供我确认；所有模块开发必须先给实施计划，获批后才编码。

分阶段使用：

1. `批准技术方案 v1.0。只设计 network-statistics 模块的实施计划，列出接口、预计修改文件、实现步骤和测试步骤，不动代码。`
2. `批准 network-statistics 模块计划 v1.0。只实施该模块并记录真实测试结果。`
3. `所有模块完成，做全量接口/业务回归，输出每个接口的入参与脱敏响应示例以及问题清单。`
4. `针对 BUG-001，先写根因和最小修复方案，修复后跑失败用例与受影响回归，并更新测试文档。`

## 4. 文档结构

```text
docs/ai-delivery/sorting-optimization/
  00-project-control.md          # 当前状态与审批记录
  01-requirements.md             # 后端需求、模块统计、开发顺序
  02-technical-design.md        # API、Mermaid 图、DDL、方案选型
  03-modules/<模块>-plan.md      # 每模块独立实施计划
  04-module-tests/<模块>-test.md # 模块独立测试记录
  05-final-test-report.md       # 全量回归与逐接口示例
  06-issue-log.md               # 缺陷复现、根因、修复和复测
  07-design-changelog.md        # 技术方案变更与审批
  08-traceability.md            # 需求→设计→代码→测试映射
  09-source-evidence.md         # 浏览器需求取证
```

## 5. 可选命令

```powershell
python .\backend-delivery\scripts\init_project.py --repo "C:\code\your-repo" --project sorting-optimization
python .\backend-delivery\scripts\init_project.py --repo "C:\code\your-repo" --project sorting-optimization --module network-statistics
python .\backend-delivery\scripts\validate_docs.py --repo "C:\code\your-repo" --project sorting-optimization
```

`validate_docs.py` 的可选 `--phase` 包含 `skeleton/requirements/design/module/final-test/release`。仅静态检查结构/占位，不保证 SQL/代码正确、不证明测试通过。

## 6. 前提与边界

- 浏览器环节依赖安装并连接 [Tencent BrowserSkill](https://github.com/Tencent/BrowserSkill) 及浏览器扩展，使用你已有的授权登录态。该 zip 不打包 BrowserSkill 本体或登录凭据。
- 文档读取、源码扫描和实际测试依赖 AI 运行端具有相应文件、Shell 与环境权限。缺少环境时报告阻塞而非虚构结果。
- 首次技术方案和每个模块计划均需要你的明确确认。任何破坏性生产变更需要单独授权。
